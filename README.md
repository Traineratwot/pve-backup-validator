# PVE Backup Validator

Automatic backup mode classification for Proxmox VE clusters.

## Problem

Different Proxmox storage types support different backup modes:

- **ZFS** — supports **snapshot** (instant, no downtime)
- **Dir/NFS** — does not support snapshot, so vzdump falls into **suspend** mode (full rsync copy) → catastrophic I/O load → potential server crash via hardware watchdog

A single VM with rootfs on dir storage can take down the entire server during backup.

## Solution

This script automatically:

1. **Discovers** all CT/VM guests in the cluster via `pvesh`
2. **Classifies** each guest by rootfs/disk storage type
3. **Generates** `/etc/pve/jobs.cfg` with correct backup modes:
   - rootfs on snapshot-capable storage → **snapshot** mode
   - rootfs on dir/NFS → **stop** mode (pause → backup → resume)

## Requirements

- [Bun](https://bun.sh) runtime
- SSH access from the machine running this script to the PVE node (root, key-based auth)
- PVE cluster API access (`pvesh`) available on the target node

## Setup

```bash
git clone https://github.com/user/pve-backup-validator.git
cd pve-backup-validator
bun install
bun run setup
```

The install script will prompt for:

| Setting | Description | Example |
|---------|-------------|---------|
| PVE host | IP or hostname of the primary PVE node | `192.168.1.10` |
| Snapshot storage | Comma-separated storage names that support snapshots | `local-zfs,fast-zfs` |
| Backup target | Storage where backups are sent | `PBS` |
| Snapshot time | Daily schedule for snapshot backups (HH:MM) | `03:00` |
| Stop time | Daily schedule for stop backups (HH:MM) | `06:30` |
| Cron job | Whether to register an hourly cron job | `y` |

Configuration is saved to `config.json` (git-ignored).

## Usage

```bash
# Run once manually
bun run start

# Install hourly cron
bun run install:cron

# Remove cron
bun run uninstall:cron
```

## Classification

| Storage type | Backup mode | Behavior |
|-------------|-------------|----------|
| Any in `snapshotStorage` list | **snapshot** | Fast, non-blocking |
| Everything else | **stop** | Guest paused during backup |

To add a new storage type, edit `config.json` and add its name to the `snapshotStorage` array.

## Configuration

`config.json` is generated by the install script:

```json
{
  "pveHost": "192.168.1.10",
  "snapshotStorage": ["local-zfs"],
  "backupTarget": "PBS",
  "schedule": {
    "snapshot": "0 3 * * *",
    "stop": "30 6 * * *"
  }
}
```

## Project Structure

```
src/
  index.ts        — entry point, orchestration
  classify.ts     — classifies CT/VM by storage type
  jobs.ts         — generates /etc/pve/jobs.cfg
  ssh.ts          — SSH exec helpers for PVE nodes
  config.ts       — loads config.json
  schemas.ts      — TypeScript types
  install.ts      — interactive setup (prompts)
  install-cron.ts — registers hourly cron job
  uninstall.ts    — removes cron job
  cron-handler.ts — Bun.cron wrapper
```

## How It Works

1. Queries `pvesh get /cluster/resources --type vm` to enumerate all guests
2. For each guest, reads config via `pvesh get /nodes/{node}/{type}/{vmid}/config`
3. Determines storage from rootfs (CT) or first disk (VM)
4. Groups guests into snapshot/stop categories
5. Writes a unified `jobs.cfg` to `/etc/pve/jobs.cfg` (cluster-wide in Proxmox)
6. Restarts the PVE scheduler to pick up changes

## Important

- The script **only writes** `/etc/pve/jobs.cfg`. It does **not** modify VM/CT configuration files, tags, mount points, or any other settings.
- `/etc/pve/jobs.cfg` is cluster-wide in Proxmox — written once, applied everywhere.
- Job IDs are regenerated on each run (random hex). Previous jobs are fully overwritten.
