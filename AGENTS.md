# AGENTS.md

## Runtime

Bun-only (not Node). Uses `bun.lock`, `import.meta.main`, `Bun.spawn`, `Bun.cron`. Do not add Node-specific shims or polyfills.

## Commands

- `bun install` — install deps
- `bun run setup` — interactive setup (prompts for PVE host, storage, schedules → writes `config.json`)
- `bun run start` — classify guests and write `/etc/pve/jobs.cfg`
- `bun test` — run tests (mocks config, tests pure logic)
- `bun run install:cron` / `bun run uninstall:cron` — register/remove hourly cron job

No lint, typecheck, or formatter commands exist.

## Architecture

Single flat `src/` directory, no packages. All logic runs locally and reaches the PVE cluster over SSH:

- `config.ts` — loads `config.json` (user-specific, git-ignored). Exports `loadConfig()`.
- `ssh.ts` — SSH to the PVE host from config. All PVE interactions go through `pveExec*` / `pveWriteFile`.
- `classify.ts` — queries `pvesh` on the PVE node to determine rootfs/disk storage, returns `ClassifiedGuest`.
- `jobs.ts` — generates `jobs.cfg` content (pure function, safe to test locally).
- `index.ts` — orchestration: enumerate guests → classify → write `jobs.cfg` → restart scheduler.
- `cron-handler.ts` — thin `Bun.cron` wrapper that calls `main()`.
- `install.ts` — interactive setup using `prompts` library. Generates `config.json`.
- `schemas.ts` — TypeScript types only (no valibot, no runtime validation).

## Scope

**The script only writes `/etc/pve/jobs.cfg`.** It does not touch VM/CT `.conf` files, tags, mount points, or any other PVE configuration.

`/etc/pve/jobs.cfg` is cluster-wide in Proxmox — written once, applied across all nodes.

## Configuration

User config lives in `config.json` (git-ignored, generated by `bun run setup`):

```json
{
  "pveHost": "<IP or hostname>",
  "snapshotStorage": ["local-zfs"],
  "backupTarget": "PBS",
  "schedule": {
    "snapshot": "0 3 * * *",
    "stop": "30 6 * * *"
  }
}
```

- `snapshotStorage` — list of storage names treated as snapshot-capable. Anything not in this list gets stop mode.
- `backupTarget` — where backups are sent (PBS, NAS, etc.).
- `schedule` — cron expressions for each backup mode.

To add new ZFS pools, append their names to `snapshotStorage` in `config.json`.

## Key conventions

- CT classification uses `rootfs` key; VM classification scans disk keys (`scsi*`, `ide*`, `sata*`, `virtio*`).
- Job IDs are random hex (`backup-validator-XXXXXXXX`), regenerated each run — previous jobs are fully overwritten.
- Tags use semicolon separators in Proxmox, but this script does not manage tags.
- Storage name is extracted from the first `:` segment of Proxmox storage references (e.g. `local-zfs:subvol-...` → `local-zfs`).
